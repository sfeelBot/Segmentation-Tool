### 구현 방식 추천 — (a) SVG 아이콘 + QIcon
1인/소규모 유지보수 데스크탑 툴이라는 전제하에 3안을 비교:
- **(a) SVG + QIcon [추천]**: MIT/ISC 라이선스 아이콘 팩(Feather/Lucide류)에서 15~18개를 골라
  `app/resources/icons/*.svg`로 보관, `QIcon(path)` 또는 `QSvgRenderer`로 로드. `currentColor`
  자리만 accent색으로 치환하면 hover/checked 상태도 같은 파일로 커버. 초기 에셋 파이프라인
  구축비용은 있지만 아이콘 개수가 적어 일회성이고, OS/폰트에 무관하게 렌더링이 일관됨 —
  "이모지 컬러폰트 렌더링 불안정"이라는 문제의 근본 원인을 실제로 없앤다.
- **(b) QPainter 직접 드로잉**: 외부 의존성 0이 유일한 장점. 15개 도형(브러시 털, 버킷
  손잡이 등)을 좌표로 손코딩해야 해 (a)보다 초기비용이 크고 결과물 품질도 낮기 쉬움 —
  이 프로젝트 규모엔 과설계로 판단, 비추천.
- **(c) 유니코드 기호 교체**: 비용 최저지만 근본 원인(이모지 폰트 렌더링)을 해결 못함.
  대신 **2단계 "장식 이모지 제거"에는 적합** — 텍스트로 바꾸거나 이미 모노톤인 기호
  (`·`/`•`/`▲`/`✕`)는 유지.
- 목업의 "After" 아이콘은 실제로 (a) 방식대로 그린 인라인 SVG(선굵기 1.6px 통일, 폴리곤/
  브러시/버킷/지우개/영역지우개/선택/팬 7종 + 참고용 부가액션)라 구현 시 기대 형태에 가까움.

### 4그룹 재설계 요지
1. **`labeling_tab.py` 툴바 7종**: 이모지 단독(16px) → SVG 라인 아이콘, 활성 도구만
   accent(`#60a5fa`) 배경/테두리. 텍스트 라벨은 안 붙임(7개 다 붙이면 툴바 과밀) — 대신
   형태 자체를 명확히 구분. 툴팁에 단축키 병기 유지.
2. **`image_browser.py` 상태기호 3종**: 색상만 다르던 것을 유지하되(모양은 이미 채움원/체크/
   빈원으로 구분됨) 크기·선굵기 확대 + 팔레트를 `main.py` 표준값(`#10b981`/`#60a5fa`)으로
   교체해 대비 개선. 범례 유지.
3. **`training_progress_dialog.py` STATUS_ICON 5종**: waiting(빈 원)/running(accent 채움
   원+테두리)/done(초록 원+체크)/error(빨강 원+X)/stopped(회색 사각) — 색상+모양 이중 구분.
4. **`log_panel.py` 로그레벨**: DEBUG(`·`)/INFO(`•`)는 이미 모노톤이라 유지, WARNING(`▲`)/
   ERROR(`✕`)도 유지(두께만 통일), CRITICAL의 `🚨`(컬러 이모지)만 같은 기하기호 계열 `■`로
   교체 — 이 항목만 이모지 폰트 의존을 완전히 제거.

### 구현 시 참고 — 주의사항
- **QTreeWidgetItem 구조 제안**: `image_browser.py`의 `_make_tree_item`/`_make_folder_item`
  패턴을 그대로 참고하되, 추론 탭은 라벨 상태 개념이 없으므로 상태기호(`●`/`✓`/`○`) 대신
  UserRole에 Path만 저장하고 텍스트는 파일명만 표시. 목업에서는 절충안으로 행 왼쪽에
  18~24px 미니 썸네일(`QIcon`/`QPixmap` 스케일)을 얹는 것을 제안했음 — 스펙 문서가 이미
  "가능한 절충"으로 언급한 내용이라 구현 재량으로 반영 여부 결정 가능(사용자 재확인 불필요).
- **세로 QSplitter 초기 비율**: `setSizes()`로 기존 stretch 비율(3:2, 2:3 등)과 동일한
  픽셀 비율을 지정할 것 — 목업은 이 "초기 상태는 기존과 동일, 이후 자유 조정"을 전제로
  그렸으므로 구현이 초기 비율을 다르게 잡으면 목업과 어긋난다.
- **`ClassPanel`/`_queue_list`/체크포인트테이블 상한 제거**는 상위 컨테이너가 QSplitter로
  바뀐 뒤에만 의미가 있다(사용자가 이미 확인한 전제) — 상한만 먼저 제거하고 스플리터 전환이
  누락되면 레이아웃이 무너질 수 있으니 두 변경을 같은 커밋/같은 검증 라운드에서 함께 처리할 것.
- 라운드 3(정보 추가) 대상은 이번 목업 범위 밖 — 신뢰도 컬럼, LR 표시, 줌/이미지크기 표시 등은
  별도 목업 필요.

분리 유지. 그룹 경계는 굵은 실선(`#374151` 2px), 같은 그룹 안 zone 구분은 점선(`#2a2f38`
1px)으로 시각적으로 구분해 "그룹 경계"와 "zone 구분"을 다른 강도로 표현. 선택 강조(파랑
`#1e3a5f`)가 있던 행(cap_0182.jpg 외곽 존)은 이미지명 셀(병합 셀)은 그룹 배경을 유지하고
zone 행 3개 셀만 강조색을 유지하도록 분리 — 병합 셀과 강조 행이 섞이면 "이미지 전체가
선택됐다"는 오해를 줄 수 있어 의도적으로 나눔.

구현 메모(목업은 시각적 병합만, 실제 구현 방식은 구현 에이전트 판단): `QTableWidget`의
`setSpan()`으로 플랫 테이블 유지 + span만 적용하는 안과, `QTreeWidget`(이미지=부모 행,
존=자식 행, 기본 펼침)으로 구조 자체를 바꾸는 안 둘 다 후보 — 전자는 기존 Excel/클립보드
내보내기 로직(`export_zone_percentages_to_excel`, `_on_copy_clipboard`)이 이미 플랫
`rows`/`blob_rows` 리스트 기반이라 변경이 적고, 후자는 접기/펼치기 같은 부가 기능을 공짜로
얻지만 선택 로직(`currentRowChanged` 류)과 내보내기 쪽 매핑을 더 손봐야 한다 — 구현
난이도·내보내기 코드 재사용성 기준으로는 `setSpan()` 쪽이 더 가벼운 선택일 가능성이 높다고
판단되나 결정은 구현 에이전트에게 맡김.

### 2. 필터링 기능 추가
Long/Wide 탭 공통 상단에 필터 바 신규 — 이미지명 검색창(돋보기 아이콘) + 존 다중선택
(선택된 존을 칩/태그로 표시, "+ 존 선택" 드롭다운 트리거) + 우측 "N / 전체건수 표시" 카운터
+ "초기화" 버튼. 사용자가 필터 기준을 구체적으로 지정하지 않아 "이미지명 검색 + 존
다중선택"을 기본값으로 제안 — 가장 흔한 요구(특정 이미지 찾기, 특정 존만 보기)를 구현
비용 최소로 커버한다는 판단.

**디자인 의견 — 비율(%)/최대 blob 픽셀수 임계값 필터는 이번에 넣지 않음(2차 확장 후보)**:
현재 요구사항이 "결과를 찾아보기 쉽게"였지 "이상치를 자동으로 걸러내기"가 아니었고, 임계값
필터는 UI 요소(범위 슬라이더 또는 min/max 입력 2개 × 2열 = 4개 컨트롤)가 늘어나는 데 비해
지금 샘플 데이터 규모(수십~수백 행)에서는 이미지명+존 필터만으로도 테이블 스크롤 탐색이
충분히 가능해 과설계 우려가 크다고 판단했다. 실제 사용 중 "비율 X% 이상만 보고 싶다"는
요청이 나오면 그때 필터 바에 세 번째 그룹(비율 슬라이더 또는 min 입력)을 추가하는 것을
권장 — 지금 레이아웃(필터 바가 가로로 여유 있게 설계됨)은 이 확장을 수용할 공간이 이미
있다.
