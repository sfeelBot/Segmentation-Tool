순수 컨투어를 그대로 경계로 쓸 경우 그 불량 튀어나온 부분까지 경계 모양에 반영되어 존
계산이 왜곡된다는 뜻. 참고 이미지의 빨간 라인도 다시 보면 "에지를 있는 그대로 따라가는
자유곡선"이 아니라 "실제 픽셀 위치에 최대한 딱 맞는 원"이 사용자의 원래 의도였음이 이번
메시지로 최종 확정. 아직 구현 착수 전(코드 변경 없음)이라 스펙+로드맵만 재정정.

### 한 일
- **판단 2 재작성(2차, 최종)**: 데이터 모델을 `Contour(id, points)`에서 다시
  `Circle(id, cx, cy, r)`로 되돌림. 단 1차 정정에서 조사한 Canny+findContours 기반
  검출 흐름은 폐기하지 않고, 파이프라인 마지막 단계로 **강건한 원피팅**을 추가하는
  형태로 합침: (1) `cv2.Canny`→`cv2.findContours(RETR_LIST)`로 폐곡선 후보 추출(유지),
  (2) 원형도(4π·area/perimeter²)+면적 필터로 링 후보 선별(유지), (3) **신규** — 선별된
  컨투어 점들에 원 피팅. `cv2.minEnclosingCircle`은 이상치(녹 튀어나온 부분) 하나에도
  반지름이 확 커질 수 있어 부적합 판정, 대신 **Kasa 대수적 최소자승 원피팅**
  (`x²+y²=Dx+Ey+F` 선형화 후 `numpy.linalg.lstsq`, `scipy` 불필요)을 채택하고 1차
  피팅 후 잔차 큰 점을 제외해 **1~2회만 재피팅**하는 단순 반복으로 이상치에 강건하게
  함(RANSAC 라이브러리 등 과공학 배제 — YAGNI). 최종 결과는 다시 독립된 `(cx,cy,r)` 목록.
- **정렬 기준 원복**: 면적 내림차순(1차 정정)에서 반지름 오름차순(원래 판단 2)으로 복귀

  2건이 추가로 필요함을 새로 확인** — 이전 초안의 "수정 없이 그대로 import" 판단을
  정정:
  - `set_item_status()`/`clear_status()`(상태아이콘+배지) — 이 위젯엔 없던 기능,
    `image_browser.py`의 기존 상태기호(●/✓/○) 관례를 재사용하도록 명시(새 아이콘
    언어 발명 금지).
  - `set_multi_select()`/`selected_paths()`(다중선택) — 버튼 문구 "**선택** 이미지
    일괄 처리"가 요청 2 원문("폴더 전체 또는 **선택한 여러 장**")을 반영한 것임을
    확인해, 기존 `SingleSelection` 고정을 깨지 않으면서(옵트인) `ExtendedSelection`을
    추가 지원하도록 설계. `selected_paths()`는 선택이 비어 있으면 `paths()`(전체
    목록)를 반환하도록 해 "전체 선택" 버튼 없이도 기본값이 "폴더 전체 처리"가 되게
    함(라더: 새 UI 요소 대신 빈 선택=전체라는 관례로 단순화).
  - 두 API 모두 `inference_tab.py`(기존 호출부)는 호출하지 않으므로 회귀 없음 —
