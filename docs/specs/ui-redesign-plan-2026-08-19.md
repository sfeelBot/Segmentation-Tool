# UI/UX 재편 스펙 — 학습·추론·라벨링 탭 (2026-08-19)

사용자 요청: "레이아웃별 움직일 수 없고 각종 정보들이 부족" — 레이아웃(리사이즈/재배치 불가)과
표시 정보 부족 두 축을 모두 개선. 범위: `training_tab.py`, `inference_tab.py`,
`labeling_tab.py` + 관련 위젯(`config_form.py`, `overlay_viewer.py`, `annotation_canvas.py`,
`class_panel.py`). 대상 코드 감사는 Explore 에이전트가 완료(아래 내용은 그 결과를 그대로
반영). 성능 개선 라운드(R1~R6)가 같은 파일을 다수 건드리므로 **그 작업이 전부 완료된 뒤
착수**하도록 로드맵에 블로커로 걸어뒀고, 2026-08-19 기준 R1~R6 전체 완료로 착수 가능 상태.

이 문서에서 "라운드"는 성능 개선 R1~R6와 구분되는 별도 번호 체계(1, 2, 3)를 쓴다.

---

## 원칙

- 완전 무제한 리사이즈가 항상 정답은 아니다 — 범례처럼 너무 좁아지면 못 읽는 위젯은
  **최소 크기는 유지하고 상한만 없애거나 넓힌다**.
- 정보를 추가할수록 화면이 복잡해지는 트레이드오프가 있다 — 어디까지 늘릴지는 기획이
  결정하지 않고 `docs/decisions-needed.md`에 등록해 사용자 확인을 받는다.
- 코드 변경 범위가 큰 파일(`annotation_canvas.py` 1638줄, `inference_engine.py` 핵심 로직)을
  건드리는 항목은 **최소 침습 패치**(기존 로직은 그대로, 필요한 지점에 시그널/필드만 추가)로
  범위를 좁힌다.

#### 정보 추가
- **현재 학습률(LR) 표시** — 스케줄러 9종이 있는데도 상태 행(`_lbl_status`, L264~273)에 현재

- **체크포인트 리스트 항목 보강** — `_ckpt_list`(L307~311)가 파일명만 표시. 같은 epoch의
  val_loss/IoU를 항목 텍스트에 덧붙이면(`epoch_0012.pt · val=0.231 · IoU=0.812`) 메트릭
  테이블과 대조하러 스크롤할 필요가 없어짐.
- (참고) "전체 예상 시간"은 `_lbl_total_eta`(L249)로 이미 존재 — 추가 불필요.
- **보류 후보(범위 밖 제안)**: 학습 중 GPU 메모리 사용량 실시간 표시 — `cuda_diag.py`가

  `torch.cuda.memory_allocated()` 폴링 추가가 필요해 범위가 커짐 — 이번 라운드에서는 제외,
  필요성 재확인되면 별도 스파이크로 검토.

#### 이미지 목록 검색/정렬/폴더 기능 부재 (2026-08-20 추가 요청)

사용자가 스펙 확인 전 추가로 짚은 불편: "이미지 로드하고 그랬을 때 정보량이 부족해. 폴더
sort 기능, 검색기능도 포함해줘." — 확인 결과 **추론 탭의 이미지 목록**(`_img_list`,
L128~134, `QListWidget` IconMode + 썸네일)을 가리킴. 라벨링 탭 `ImageBrowser`
(`app/widgets/image_browser.py`)는 검색(디바운스 200ms)·정렬 4종(파일명↑↓/폴더/완료↑/
미완료↑)·폴더 그룹핑 트리뷰·라벨 상태 아이콘을 모두 갖췄지만, 추론 탭은 검색창도 정렬도
폴더 그룹핑도 전혀 없는 순수 `QListWidget`이다. 기존 "레이아웃 유연성" 표는 이 목록의
**폭 제약**만 다뤘고 기능 자체의 부재는 다루지 않았다 — 이 절에서 별도로 다룬다.

**옵션 (a) `ImageBrowser` 위젯 재사용 — 기각.**
`image_browser.py` 재확인 결과 다음 지점들이 추론 탭 용도와 구조적으로 어긋난다.
- `reload()`(L217~227)가 스캔 루트를 `_project.images_dir()`로 **하드코딩**한다. 반면
  추론 탭은 `QFileDialog.getOpenFileNames`/`getExistingDirectory`로 **프로젝트 밖 임의
  경로**를 선택하는 것이 기본 워크플로우(L203~224) — 이 전제 자체가 다르다. 재사용하려면
  스캔 루트를 매개변수화해야 하는데, 그러면 `_apply_display`/`_build_folder_tree`/
  `_rel_name`(L397~402, `images_dir()` 기준 상대경로 계산) 등 내부 다수 지점이
  `_project.images_dir()`를 직접 참조하고 있어 파급 범위가 커진다.
- 상단 버튼 `이미지 추가`/`폴더 추가`/`삭제`(L140~148)가 파일을 프로젝트 `images_dir`로
  **복사**하거나 원본을 **삭제**하는 편집 액션이다(`_on_add`, `_on_add_folder`,
  `_on_delete`, L291~369). 추론 입력은 원본 파일을 그대로 참조만 해야 하므로 이 버튼들은
  숨기는 게 아니라 아예 다른 동작(파일 선택 다이얼로그 트리거)으로 바꿔야 해 "숨기고 재사용"
  수준을 넘어선다.
- 라벨 상태 아이콘(●라벨링됨/✓OK/○미라벨, `_STATUS_STYLE`)과 정렬 기준 중 "완료↑"/
  "미완료↑"(`get_label_status()` 기반)는 어노테이션 개념이라 추론 입력 이미지(프로젝트
  밖일 수도 있는 임의 이미지)엔 의미가 없거나 오해를 부른다.
- 추론 탭은 **썸네일 아이콘 그리드**(`IconMode`, THUMB=64px)인데 `ImageBrowser`는
  텍스트+상태글리프 트리뷰라 썸네일이 없다 — 시각적으로도 다른 위젯.
- 무엇보다 `ImageBrowser`는 라벨링 탭에서 활발히 쓰이는 **공유 위젯**이다. 위 항목들을
  전부 매개변수화/조건분기하면 라벨링 탭에 회귀 리스크가 전이된다.

**옵션 (b) 추론 탭 전용 경량 구현 — 채택.**
검색 디바운스(`QTimer` + `textChanged`)와 정렬(정렬 key 함수 + `QComboBox`)은 로직 자체가
각각 10~20줄 내외로 작고 이미 `ImageBrowser`에서 검증된 패턴이다. 위젯 전체가 아니라
**패턴만** 재사용해 추론 탭 전용 소형 컴포넌트를 새로 만드는 쪽이 리스크가 낮다.
- `_img_list`(QListWidget IconMode, 썸네일 유지) 위에 검색 `QLineEdit`(placeholder
  "🔍 파일명 검색...", 200ms 디바운스, `ImageBrowser`와 동일 파라미터) 추가.
- 정렬 `QComboBox`: **파일명↑ / 파일명↓ / 폴더** 3종만 제공(완료/미완료 정렬은 어노테이션
  상태 개념이 없으므로 제외).
- **폴더 그룹핑 — 2026-08-20 사용자 결정: 트리형(라벨링 탭과 동일 구조) 채택.** 처음 제안한
  "정렬 옵션만" 대신 `ImageBrowser`의 `_build_folder_tree()`(폴더 헤더+접기/펼치기)와 동등한
  구조를 추론 탭에도 둔다. **트레이드오프**: 현재 `_img_list`의 64px 썸네일 아이콘 그리드
  (`IconMode`)는 트리뷰(`QTreeWidget`, 텍스트+아이콘 행)로는 유지할 수 없다 — 트리 노드
  안에 작은 썸네일 아이콘(예: 24~32px)을 항목 왼쪽에 넣는 절충은 가능하나, 지금 같은 큰
  그리드 프리뷰는 포기해야 한다. 이 트레이드오프는 사용자가 "라벨링 탭과 동일"을 명시적으로
  선택하며 감수하기로 했다 — 구현 시 다시 확인받을 필요 없음. 여전히 `ImageBrowser` 클래스
  자체 재사용은 기각 사유(위 "옵션 (a) 기각" 근거: 하드코딩된 스캔 루트, 편집 버튼, 라벨
  상태 개념)가 그대로 유효하므로, **`QTreeWidget` 기반 폴더 트리 UI 패턴만 참고해 추론 탭
  전용 컴포넌트로 새로 구현**한다.
- `_load_paths()`(L226~239)가 이미 전체 경로 리스트를 들고 있으므로 필터/정렬은 여기 붙는
  `_all_paths`(전체) → `_apply_display()`(필터+정렬 후 `_img_list` 재구성) 형태로
  `ImageBrowser`와 동일한 2단계 구조를 따르되, 코드는 별도 파일/메서드로 분리.

#### 정보 추가 — 우선순위 최상 (사용자 워크플로우상 명백한 갭)
- **신뢰도(confidence) 표시 부재** — 현재 `ClassStat`(`inference_engine.py` L18~23)에
  `pixel_pct`만 있고 confidence 정보가 전혀 없음. 두 경로 모두 소프트맥스 확률에 접근
  가능한 지점이 있음:
  - `run()`(L33~98): `output`이 raw logits이라 `torch.softmax(output, dim=1)` 한 줄 추가로
    클래스별 평균 confidence(해당 클래스로 분류된 픽셀들의 max-softmax-prob 평균) 계산 가능.
  - `run_sliding_window()`: 이미 패치별 `torch.softmax(out, dim=1)`(L165)를 누적(`acc`)하고
    있어 최종 `acc.max(axis=0)`에서 confidence map을 바로 뽑을 수 있음(병합 로직 자체는
    건드리지 않고 부가 계산만 추가).
  - `ClassStat`에 `mean_confidence: float` 필드 추가 → 범례 테이블(`_legend_table`, L170~176)에
    "신뢰도(%)" 컬럼 추가.
  - **스코프 경계 — 2026-08-20 사용자 확정**: "클래스별 평균 confidence 통계"까지만. 저신뢰도
    픽셀 하이라이트/히트맵 오버레이 같은 후속 기능은 범위 밖(별도 요청 시 재검토).
- **처리 시간 표시** — `_on_run()`(L311~360)에서 추론 소요 시간을 측정하지 않음. 간단한
  `time.perf_counter()` 래핑으로 `_lbl_model_info` 옆 또는 별도 라벨에 "처리시간: 234ms"
  표시 — 저비용.
- **원본/추론 해상도 정보** — `_infer_size_from_ckpt(ckpt)`로 결정되는 추론 해상도가 화면에
  안 보임. 원본 크기와 함께 "원본 1920×1080 → 추론 512×512" 형태로 표시하면 resize 모드에서
  디테일 손실 가능성을 사용자가 미리 짐작할 수 있음.

#### 스타일
- **스플리터 hover 강조색 누락** — 학습/라벨링 탭엔 있는(`QSplitter::handle:hover`) 파랑 강조가
  추론 탭 스플리터(L121)엔 없음. `main_splitter` 정의부에 동일 스타일시트 추가 — 트리비얼.

#### 정보 추가

## 실행 순서 (라운드 1~3)

### 라운드 1 — 제약값 조정 + 스타일 통일 (목업 불필요, 저리스크)
순수 `setMaximumWidth`/`setMaximumHeight`/`setFixedWidth` 등 숫자·스타일시트 조정만.
새 정보 패널·레이아웃 구조 변경 없음.
1. 추론 탭 스플리터 hover 강조색 추가.
2. 학습 탭 `side_panel` 상한 제거.
3. 추론 탭 범례(190px 고정→가변) · 이미지목록(180px 상한→완화) 폭 제약 완화.

### 라운드 2 — 레이아웃 재구조화 (디자인 목업 필요, 중리스크)
기존 `QVBoxLayout`/고정 stretch를 `QSplitter`로 바꾸는 구조 변경. 배치가 바뀌므로 목업으로
먼저 확인.
1. 라벨링 탭 좌 패널(이미지브라우저↔클래스패널), 우 패널(어노테이션목록↔로그패널) 내부
   수직 QSplitter 전환.
2. 학습 탭 큐 영역(큐 박스 ↔ 진행상태+그래프) 수직 QSplitter 전환, `_queue_list` 상한 제거.
3. 추론 탭 상단(컨트롤+체크포인트테이블) ↔ 메인 뷰어 영역 수직 QSplitter 전환.
4. **추론 탭 이미지 목록에 검색+정렬 기능 신규 추가**(2026-08-20 요청분, 위 "이미지 목록
   검색/정렬/폴더 기능 부재" 절 참고) — `ImageBrowser` 재사용이 아니라 추론 탭 전용 경량
   컴포넌트 신규 구현. 순수 상수 조정이 아니라 검색바+정렬콤보라는 새 서브레이아웃이
   목록 패널에 추가되는 구조 변경이라 라운드 1이 아닌 라운드 2에 배치. 다만 `ImageBrowser`
   등 공유 위젯을 건드리지 않는 격리된 신규 파일이라 이 라운드의 다른 항목(기존 위젯의
   레이아웃을 직접 뜯어고치는 항목들)보다는 회귀 리스크가 낮은 편.

### 라운드 3 — 정보 추가 (디자인 목업 필요, 중~고리스크 — core/canvas 터치 포함)
새 정보를 어디에 어떤 형태로 보여줄지 배치 확인 필요. 코드 리스크가 가장 큰 라운드.
1. 추론 탭 신뢰도(confidence) 표시 — `inference_engine.py` 계산 로직 추가 + 범례 테이블
   컬럼 추가 (**최우선 항목** — 사용자가 명시적으로 짚은 갭은 아니지만 감사에서 발견된
   가장 명백한 정보 공백).
2. 추론 탭 처리시간 + 원본/추론 해상도 표시.
3. 학습 탭 현재 LR 표시(`trainer.py` payload 확장) + 체크포인트 리스트 항목 보강.
4. 라벨링 탭 이미지 크기·줌 배율 표시(`annotation_canvas.py` 시그널 추가, 최소 침습) +
   어노테이션 개수 요약.

라운드 3의 `annotation_canvas.py`(1638줄)·`inference_engine.py`(추론 핵심 로직) 변경은
구현 에이전트에게 "diff를 신규 시그널/필드 추가로 한정, 기존 그리기·추론 로직 미변경"을
명시적으로 지시할 것 — 검증 단계에서 회귀 여부를 특히 신경 써서 확인.
