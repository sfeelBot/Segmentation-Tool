## 코드 조사 결과 요약 (중요 — 신규 작업량이 예상보다 훨씬 적음)

세 요청 모두 **이미 존재하는 인프라를 그대로 재사용**하면 되고, 신규 검출/추론 로직은
전혀 필요 없다는 것이 조사의 핵심 결론이다:

- `app/core/circle_detector.py::detect_circles(bgr_np, sensitivity=0.5, params=None)`는
  Qt/모델/체크포인트 의존성이 전혀 없는 순수 함수이고, `sensitivity`(0~1 슬라이더 매핑) 외에
  `params: DetectParams`를 직접 넘기면 Canny 임계값·원형도·면적필터·모폴로지·이상치 제거
  파라미터를 전부 개별 지정할 수 있다(`DetectParams` dataclass, 13개 필드 전부 기본값 있음,
  L22-39). **요청 1은 이 함수를 그대로 부르는 새 팝업 UI만 있으면 된다.**
- `app/core/inference_engine.py::run()`/`run_sliding_window()`/`refilter()`는 이미
  `min_confidence`/`min_pixel_size`/`classes` 옵션 인자를 전부 갖추고 있다(R1에서 이미
  추가 완료, `classes` 옵션). **요청 3은 `inference_engine.py`를 전혀 건드릴 필요가 없고**,
  `zone_analysis_tab.py`가 이 인자들을 스핀박스 값으로 채워 넘기기만 하면 된다. 단,
  아래 "판단 B"에서 설명할 **기존 코드의 숨은 결함 1건**을 함께 고쳐야 threshold가 실제로
  작동한다.
- `app/widgets/inference_image_list.py::InferenceImageList`는 `app.core.project`를
  참조하지 않는 완전 독립 위젯(grep 0건 확인)이고, `load_folder(root)`(재귀 `rglob` 스캔),
  `load_files(paths)`(개별 다중 선택), 검색 디바운스, 정렬 5종, `paths()`(현재 표시 목록
  전체 반환 — 일괄 처리용으로 이미 준비된 API), `image_selected`/`display_changed` 시그널을
  전부 갖춘 상태다. **요청 2의 "폴더 단위 이미지 가져오기" 부분은 신규 위젯을 만들 필요가
  전혀 없다** — `app/widgets/image_browser.py`(라벨링 탭, 프로젝트 `images_dir()` 하드코딩
  + 비재귀 스캔이라 BUG-005로 이미 죽은 코드 판정)보다 이 위젯이 명백히 적합함을 코드로
  재확인(사용자가 예상한 대로).
- `app/core/inference_engine.py::export_blobs_to_excel(rows, out_path)`가 이미
  openpyxl 기반 내보내기 패턴(헤더 볼드, 시트 1개)을 갖고 있어, 존 퍼센티지용 내보내기
  함수도 동일 패턴을 그대로 복제하면 된다(스키마만 다름).
- `app/widgets/overlay_viewer.py::OverlayViewer.set_pixmap()`은 `InferenceResult`
  전용이 아니라 **임의의 `QPixmap`을 받는 범용 API**다(추론 결과 여부를 검사하지 않음).
  `ZoneCanvas`(OverlayViewer 상속)는 이미 원 렌더링/편집/좌표변환을 전부 갖추고 있으므로,
  **요청 1의 팝업도 `ZoneCanvas`를 그대로 재사용**할 수 있다 — 플레인 이미지를
  다운스케일 QPixmap으로 변환해 `set_pixmap()` + `set_image_size()` + `set_circles()`만
  호출하면 기존 원 렌더링·드래그 편집·Delete/우클릭 삭제가 전부 공짜로 딸려온다.

## 확정 요구사항 (사용자 답변 완료 — 재질문 불필요)

1. **오프라인 원 검출 테스트 팝업** — 이미지만 로드하면(체크포인트 불필요) `circle_detector.detect_circles()`
   결과를 미리보고 파라미터를 조절할 수 있는 별도 다이얼로그. 기존 메인 탭 플로우(추론
   필요)는 그대로 유지. 신규 검출 로직 작성 금지 — `circle_detector.py` 재사용.
2. **폴더 단위 이미지 가져오기 + 일괄 처리 (최우선)** — 폴더 선택으로 이미지 여러 장을
   한 번에 불러오고, 체크포인트 로드 1회로 폴더 전체(또는 목록)를 순차 추론+존 계산까지
   자동 수행. 원 적용 방식 기본값은 **"1번째(기준) 이미지에서 검출/편집한 원을 나머지
   전체에 그대로 적용"**, 토글로 **"이미지마다 개별 자동검출"** 모드 제공. 결과는
   이미지별 존 퍼센티지를 볼 수 있어야 함(표/엑셀 여부는 기획 판단에 위임됨).
3. **Threshold 조절(AI 신뢰도/픽셀 크기)** — 추론 탭의 `_min_conf_spin`/`_min_px_spin` +
   `engine.refilter()`(모델 재실행 없이 재필터링) 패턴을 그대로 이식. 초기 고정값은 지금은
   코드 상수로 충분(설정 UI는 나중).

## 재확인 (기존 확정 사항, 변경 없음)

판단 2(원 데이터모델), 판단 3(체크포인트→모델 재구성), 판단 4(타겟 클래스 즉석구성)는
그대로 유지. BUG-018/019(캔버스 시그널이 리스트/하이라이트 상태를 부당하게 리셋하던 패턴)
재발 방지 원칙도 신규 UI(폴더 목록↔캔버스 동기화, 결과 브라우징)에 동일하게 적용해야 함
(아래 "리스크" 절). 완전 독립 도구 원칙(프로젝트 시스템 미사용)도 유지 — `InferenceImageList`
재사용이 이 원칙과 이미 정합됨을 위에서 확인함.

## 판단 A — 오프라인 원 검출 팝업 (요청 1)

### 신설: `app/widgets/circle_detect_preview_dialog.py` — `CircleDetectPreviewDialog(QDialog)`

**승인된 구조(위 레이아웃 절 참고)**: 상단에 제목+부제("체크포인트 없이 이미지만으로
검출 알고리즘을 확인·튜닝합니다")+닫기(X) 버튼 → "이미지 열기…" 버튼+파일명 → 큰
미리보기 영역(이미지+검출된 원 오버레이, **검출 개수/소요시간 표시**) → 민감도
슬라이더+"다시 검출" 버튼 → 하단 "닫기" 버튼.

- 열기 트리거: `ZoneAnalysisTab` 상단 툴바 오른쪽 끝의 "오프라인 원 검출 테스트…" 버튼
  — 체크포인트 준비 여부와 무관하게 항상 활성화. 클릭 시 이 다이얼로그를 모달로 연다.
- 큰 미리보기 영역: `ZoneCanvas` 재사용(원 렌더링/드래그 편집/삭제가 전부 그대로 딸려옴,
  **신규 캔버스 작성 금지**).
- 이미지 로드 시 `PIL.Image` → numpy → **다운스케일 후 QPixmap 생성**(원본 20MP를 그대로
  화면에 올리면 무거움) → `canvas.set_pixmap(pixmap)` + `canvas.set_image_size(orig_w, orig_h)`.
  다운스케일 기준은 `circle_detector._MAX_DETECT_DIM`(=2048, 검출 파이프라인이 내부적으로
  쓰는 것과 동일 값)을 재사용해 "화면에 보이는 스케일"과 "검출이 실제로 분석한 스케일"을
  맞추는 것을 권장(필수는 아님 — 어긋나도 좌표는 원본 스케일로 정확히 역산되므로 시각적
  일치일 뿐). 컬러 블렌딩(`inference_engine._colorize_and_blend`)은 클래스맵이 없어 재사용
  불가 — 원본 RGB를 그대로 QImage로 변환하는 ~10줄짜리 로컬 헬퍼만 작성(신규 "검출" 로직
  아님, 단순 이미지 표시 변환).
- "다시 검출" 버튼 클릭 시: `time.perf_counter()`로 감싸 `detect_circles(bgr, sensitivity=slider값)`
  호출 → 소요시간(ms)과 `len(circles)`를 미리보기 영역 상단/옆에 표시(승인된 목업 문구
  "검출개수/소요시간 표시") → `canvas.set_circles(circles)`.
- **이전 초안의 "간단모드/고급모드(`DetectParams` 13개 필드 폼)" 제안은 승인된 목업에
  포함되지 않아 이번 라운드 범위에서 제외한다** — 팝업은 메인 탭 "자동 검출"과 동일하게
  민감도 슬라이더 1개만 노출(`detect_circles(bgr, sensitivity=s)`, `params=` 인자는 이번
  라운드에서 호출하지 않음). 사용자가 애초에 요청한 "Canny/원형도/면적/원피팅 파라미터
  튜닝"은 이 슬라이더로 충분히 커버되는 것으로 승인된 것으로 해석 — `DetectParams` 필드
  단위 노출이 실제로 더 필요해지면 "향후 확장 후보"의 후속 라운드에서 이 팝업에 접이식
  고급 섹션을 추가하면 된다(그때도 `circle_detector.py` 자체는 이미 `params` 인자를
  지원하므로 core 변경 없이 팝업 UI만 확장하면 됨).
- 원 편집: `ZoneCanvas`가 이미 지원하는 드래그 이동/반지름 조절/추가/삭제를 그대로 사용 —
  자동 검출 결과를 수동으로 미세 조정해보는 것도 이 팝업의 자연스러운 부가 기능(추가 구현
  없음).
- **범위 밖(명시적으로 하지 않음)**: 팝업에서 확정한 원/파라미터를 메인 탭으로 "적용" 버튼을
  통해 되돌려보내는 라운드트립 — 사용자가 요청하지 않았고("알고리즘 자체를 판단/튜닝하고

## 판단 B — Threshold 조절 (요청 3) — 기존 코드의 숨은 결함 동시 수정 필요

### 발견 — 오늘 당장은 안 보이지만 threshold UI를 추가하는 순간 드러나는 결함

`zone_analysis_tab.py`의 `_on_target_changed()`(L381-422)와 `_current_target_mask()`
(L426-438)는 둘 다 **`InferenceResult.raw_class_map`**(필터링 전 원본 argmax 클래스맵)을
타겟 마스크의 기준으로 쓰고 있다. 반면 `inference_engine.refilter()`가 `min_confidence`/
`min_pixel_size`에 따라 실제로 갱신하는 것은 **`InferenceResult.class_map`**(blob 단위
threshold 필터링 후 결과, `_compute_blobs_and_filter()` 참고)이다. 즉:

- 지금까지는 `_on_target_changed()`가 `refilter(..., min_confidence=0.0, min_pixel_size=0, ...)`를
  **하드코딩**으로 호출해왔기 때문에 `class_map == raw_class_map`이 항상 성립해 문제가
  드러나지 않았다.
- **이번 요청대로 스핀박스에서 threshold를 0이 아닌 값으로 바꾸면**, 오버레이 픽스맵
  (`result.overlay_pixmap`, `refilter()`가 갱신)은 threshold를 정확히 반영해 화면에 표시되지만,
  **존 퍼센티지·블랍 라벨맵은 여전히 `raw_class_map` 기준이라 threshold를 완전히 무시한다**
  — 화면은 바뀌는데 숫자는 안 바뀌는 사용자 입장에서 매우 혼란스러운 버그가 된다.
- **수정(최소 침습, 2줄)**: `_on_target_changed()`의 `target_mask = result.raw_class_map == cid`
  → `result.class_map == cid`로, `_current_target_mask()`의
  `mask = self._last_result.raw_class_map == self._target_class_id` → `class_map`으로 교체.
  둘 다 이미 `refilter()`가 반환한 최신 `class_map`을 갖고 있으므로 추가 계산 불필요.

### UI 추가 — 승인된 레이아웃 반영: 상단 툴바로 이동, 신뢰도는 슬라이더

- 위치 변경: 이전 초안은 "타겟 클래스 선택 행 근처"에 두는 것이었으나, 승인된 레이아웃에서는
  **상단 툴바 한 줄**(체크포인트/타겟클래스/신뢰도/픽셀크기/자동검출/블랍삭제모드/팝업버튼)
  안에 배치된다 — 배치 위치만 바뀌고 아래 로직은 동일.
- **위젯 종류 변경**: `inference_tab.py`는 AI 점수를 `QDoubleSpinBox`(0~100%)로 받지만,
  승인된 목업은 **"AI 신뢰도 슬라이더+값 표시"**를 명시했다 — 이 탭은 `QSlider(0~100)` +
  값을 보여주는 `QLabel`(예: `f"{v}%"`, 기존 `_sensitivity_slider`/`_lbl_sensitivity`
  쌍과 동일한 패턴, `circle_row`에 이미 있는 관례를 그대로 재사용)로 구현한다. 픽셀
  크기는 승인된 목업에도 "픽셀크기 스핀박스"로 명시돼 있어 `inference_tab.py`의
  `_min_px_spin`(`QSpinBox`, 0~100000px)을 그대로 복제.
- **초기 고정값**: 설정 다이얼로그 등 UI를 새로 만들지 않고(YAGNI, 사용자도 "지금 당장은
  아니다"로 명시), `zone_analysis_tab.py` 모듈 상단에 상수 2개
  (`_DEFAULT_MIN_CONFIDENCE = 0.0`, `_DEFAULT_MIN_PIXEL_SIZE = 0`)를 두고 스핀박스
  초기값으로 사용. 나중에 고정값을 바꾸고 싶으면 이 상수만 수정하면 됨 — "나중에 초기
  고정값을 줄 수 있도록"이라는 요청을 코드 상수 1곳으로 충분히 만족.
- 시그널: `_conf_slider.valueChanged`/`_min_px_spin.valueChanged` → **기존
  `_on_target_changed()`를 그대로 재사용**(타겟 클래스 전환 시 이미 하는 일 — refilter →
  class_map 갱신 → 블랍 라벨맵 재계산 → `_recompute_zones()` — 가 threshold 변경 시 필요한
  일과 완전히 동일하므로 새 슬롯을 만들 필요가 없다). `_on_target_changed()` 내부에서
  `refilter(..., min_confidence=self._conf_slider.value()/100.0, min_pixel_size=self._min_px_spin.value(), ...)`로
  하드코딩된 0.0/0 두 값만 교체.
- 블랍 삭제 이력(`ZoneCanvas.set_blob_data`가 호출될 때마다 초기화)은 threshold가 바뀌면
  자동으로 초기화된다 — threshold가 바뀌면 blob 구성 자체가 달라지므로 이전 삭제 이력이
  더 이상 의미 없다는 것이 맞는 동작(기존 로직이 이미 이렇게 되어 있음, 추가 처리 불필요).

### C-2. 일괄 처리 (핵심 로직, 승인된 좌측 패널 하단 컨트롤 반영)

- 승인된 UI: 좌측 패널 하단에 체크박스 **"1번째 이미지 원을 전체에 적용"**(기본 **체크**
  = 기준 이미지 원 재사용, 요청 2의 확정 기본 동작 — 체크 해제 시 이전 초안의 "이미지마다
  개별 자동검출" 모드와 동일한 의미) + **"▶ 선택 이미지 일괄 처리 (N장)"** 버튼(목록에
  2장 이상 있고, 기준 이미지에 원이 1개 이상 정의돼 있어야 활성화).
- **"선택 이미지"의 의미 — `InferenceImageList` 애디티브 확장 필요**: 버튼 문구가 "선택
  이미지"인 것은 요청 2 원문("폴더 전체 **또는 선택한 여러 장**")을 반영한 것 — 폴더
  전체가 아니라 Ctrl/Shift로 고른 일부만 처리하는 것도 지원해야 한다. `InferenceImageList`는
  현재 `SingleSelection` 고정(`_tree.setSelectionMode(...)`)이라 다중 선택이 불가능하다.
  **애디티브 API 추가**(기존 `inference_tab.py` 호출부는 그대로, 기본 동작 불변):
  - 생성자 또는 `set_multi_select(enabled: bool)`로 `ExtendedSelection` 전환 옵션 제공
    (기본값은 기존과 동일한 `SingleSelection` — `inference_tab.py`는 이 옵션을 호출하지
    않으므로 회귀 없음).
  - `selected_paths() -> list[Path]` — 다중 선택 모드에서 현재 선택된 경로 목록. **아무것도
    명시적으로 선택하지 않은 초기 상태에는 `paths()`(현재 표시 중인 전체 목록)를 반환** —
    이렇게 하면 사용자가 selection을 건드리지 않아도 버튼이 "전체 처리"로 항상 의미
    있게 동작하고(N = 전체 개수), Ctrl/Shift로 일부만 고르면 그 부분집합만 처리된다
    — 별도 "전체 선택" 버튼을 만들 필요가 없다(라더: 빈 선택=전체라는 관례가 새
    UI 요소보다 단순).
  - 버튼 라벨의 `(N장)`은 `len(selected_paths())`로 매 선택 변경마다 갱신
    (`selectionChanged` 시그널 연결).
- 처리 흐름(`inference_tab._export_all_images_to_excel()`의 `QProgressDialog` 루프
  패턴을 그대로 재사용), 대상은 `selected_paths()`(위에서 정의):
  1. 기준 이미지에서 이미 확정된 타겟 클래스 정의(`[ClassDef(0,...), ClassDef(cid, name, color)]`,
     `_on_target_changed()`가 이미 만들어 둔 것)를 **처리 대상 전체에 고정으로 재사용**
     — 같은 체크포인트를 쓰므로 클래스 id 의미가 이미지마다 바뀔 이유가 없음(모델은 1회
     로드, 이미지만 바뀜).
  2. `targets = self._img_list.selected_paths()`, `QProgressDialog(0, len(targets))` +
     취소 지원, 각 이미지에 대해:
     - 현재 표시 중인 이미지와 경로가 같고 `_last_result`가 있으면 재사용(재추론 생략,
       `inference_tab`과 동일한 최적화).
     - 아니면 `engine.run(model, path, ckpt_path, classes=고정_classes, min_confidence=.., min_pixel_size=.., opacity=0.5)`.
     - 원 목록 결정: **"1번째 이미지 원을 전체에 적용" 체크 시(기본값)** = `self._canvas.get_circles()`
       (기준 이미지 원, 반지름 오름차순 `(cx, cy, r)`); **체크 해제 시(이미지마다 개별
       자동검출)** = `detect_circles(bgr_of(this_image), sensitivity=슬라이더값)`(메인 탭의
       "자동 검출" 버튼과 동일 호출 — 신규 로직 아님, 배치로 반복 호출할 뿐).
     - 처리 중/완료 시마다 `self._img_list.set_item_status(path, "processing"/"done", badge=...)`
       호출(C-1의 애디티브 API) — 완료 배지는 해당 이미지의 존 퍼센티지 중 하나(예: 가장
       바깥쪽 존, 구현 재량)를 대표값으로 사용.
     - **해상도 방어**: "전체 적용" 체크 시 이번 이미지의 크기가 기준 이미지와 다르면(같은
       카메라/렌즈/거리 전제가 깨진 예외 케이스), 원 좌표를 `(w_i/w_ref, h_i/h_ref)` 비율로
       비례 스케일해 적용 — 몇 줄짜리 안전장치이므로 포함 권장(정교한 정합/워핑은 아님,
       YAGNI 선을 넘지 않는 선에서). 크기가 같으면 그대로 사용.
     - `zones = zones_from_circles([Circle(...) for ...], (h, w))`,
       `target_mask = result.class_map == target_cid`(판단 B와 동일하게 `class_map` 사용 —
       threshold가 배치에도 일관되게 적용됨), 각 zone에 대해 `zone_stats(zone.mask, target_mask)`.
     - **블랍 클릭 삭제는 배치에 적용하지 않는다**(v1 명시적 제외) — 블랍 삭제는 본질적으로
       사람이 눈으로 보고 판단하는 수동 작업이라 자동화 루프 안에 넣을 수 없고, 넣으려면
       이미지마다 다이얼로그를 띄워야 해 "과한 대화상자 남발"이 된다(요청 원문이 경계한
       바로 그것). 대신 아래 "결과 확인" 절의 브라우징으로 사용자가 특정 이미지를 골라
       기존 단일 이미지 플로우(블랍 삭제 포함)로 직접 열어볼 수 있으므로 완전히 막힌 것은
       아님.
     - 결과 행 누적: `(image_name, zone_name, pct)` 튜플 리스트(long format — 아래 참고).
  3. 완료 후 결과를 담은 신규 다이얼로그로 표시(C-3).

- **결과 확인(이미지별로 볼 수 있어야 한다는 요구사항) — 캐시 없이 재사용으로 해결**:
  일괄 처리 도중 원본 해상도 배열(`raw_class_map`/`confidence_map`, 20MP 기준 이미지당
  수십~백MB 단위)을 이미지 개수만큼 메모리에 들고 있는 것은 폴더 규모가 커지면 위험한
  설계다(캐시하지 않는 것으로 결정). 대신: 사용자가 목록(`InferenceImageList`)에서 특정
  이미지를 클릭하면 그 이미지가 "새 기준 이미지"처럼 로드되고, 기존 단일 이미지 플로우
  (▶ 추론 실행 → 타겟 클래스는 이미 고정돼 있으니 자동 반영 → 자동 검출 버튼 또는 기준
  원 그대로 보기)로 **다시 그 자리에서 계산**해 확인하면 된다 — 결정론적 계산(같은
  체크포인트+같은 threshold+같은 sensitivity면 항상 같은 결과)이므로 일괄 처리 때 나온
  숫자와 100% 일치함이 보장된다. 이 방식은 신규 캐시 자료구조·메모리 관리 코드를
  전혀 추가하지 않고 기존 파이프라인 재사용만으로 요구사항을 만족한다(라더 2단계:
  이미 있는 것 재사용).

### C-3. 결과 표시 + Excel 내보내기(신규 다이얼로그, 작지만 별도 라운드로 분리 가능)

- 신설: `app/widgets/zone_batch_result_dialog.py` — `ZoneBatchResultDialog(QDialog)`.
  `QTableWidget(0, 3)`(열: 이미지 / 존 / 타겟 비율(%)) — **long format**을 채택한 이유는
  "개별 자동검출" 모드에서 이미지마다 원 개수(=존 개수)가 달라질 수 있어 wide format(이미지
  × 존 열)이 들쭉날쭉해지기 때문(라더: 두 포맷 다 구현하는 것보다 하나로 통일이 더 단순).
  피벗이 필요하면 Excel에서 사용자가 직접 피벗하면 됨(v1 범위 아님).
  하단에 "Excel로 내보내기" 버튼.
- 신설: `app/core/zone_metrics.py::export_zone_percentages_to_excel(rows: list[tuple[str, str, float]], out_path: Path) -> None`
  — `inference_engine.export_blobs_to_excel()`과 동일한 openpyxl 패턴(헤더 볼드, 시트 1개)을
  스키마만 바꿔 복제(열: 이미지파일명/존이름/타겟비율(%)). 신규 의존성 없음(openpyxl은 이미
  프로젝트 의존성).
- **엑셀 내보내기 필수 여부 판단(사용자가 기획에 위임)**: **포함을 권장** — 인프라
  (`openpyxl` 패턴, 다이얼로그 골격)가 이미 존재해 추가 비용이 매우 낮고(신규 함수
  15줄 내외 + 버튼 1개), "일괄 처리"라는 기능의 자연스러운 종착점(보고서 산출)이라 화면
  테이블만으로는 나중에 재요청될 가능성이 높다고 판단. 다만 **화면 표시(테이블)와 완전히
  분리 가능한 서브스텝**이므로, 검증 중 시간이 부족하면 이 부분(C-3 후반부, 엑셀 버튼)만
  제외하고 표 표시까지만으로 라운드를 마무리해도 무방하도록 아래 라운드 분할에서 별도
  스텝(3c)으로 뗌.

## 라운드 분할 제안

우선순위(사용자가 "가장 중요"라고 밝힌 것)와 별개로, **의존관계·리스크 기준으로 순서를
정했다** — threshold 수정(요청 3)이 일괄 처리(요청 2)의 퍼센티지 계산 정확성의 전제가 되므로
먼저 끝내두는 것이 재작업을 줄인다. 요청 1(팝업)은 완전히 독립적이라 아무 때나 껴도 되지만
가장 리스크가 낮아 첫 라운드로 배치한다(순서 자체는 승인된 레이아웃과 무관하게 그대로
유지 — 아래는 각 라운드 설명에 레이아웃 세부사항만 반영한 것).

**3분할 레이아웃 자체(툴바 신설 + `QSplitter` 3-way 확장)는 어느 요청에도 종속되지 않는
순수 컨테이너 변경**이므로, 가장 먼저 착수하는 라운드 1에서 툴바/3분할 뼈대까지 함께
잡아두고 이후 라운드는 그 뼈대 안에 기능만 채워 넣는 방식으로 진행한다(레이아웃을 나중에
또 갈아엎는 재작업 방지).

1. **라운드 1 (요청 1, 저리스크, 완전 독립 + 레이아웃 뼈대 착수)** —
   - 레이아웃: `zone_analysis_tab.py`의 기존 2분할(`QSplitter(canvas|side)`)을 좌·중·우
     3-way `QSplitter`로 확장(좌측 패널은 이 라운드에선 아직 비워두거나 자리만 잡음 —
     내용물은 라운드 3에서 채움), 기존 산발적인 버튼 행들(`file_row`/`run_row`/`target_row`/
     `circle_row`)을 상단 툴바 한 줄로 통합(체크포인트/타겟클래스/자동검출/블랍삭제모드
     — 신뢰도·픽셀크기는 라운드 2에서 이 툴바에 추가). 커스텀 모델 코드 박스는 툴바
     아래 조건부 표시로 위치만 이동.
   - 기능: `circle_detect_preview_dialog.py` 신설(승인된 팝업 구조: 제목+부제+닫기 →
     이미지 열기+파일명 → `ZoneCanvas` 미리보기(검출개수/소요시간 표시) → 민감도
     슬라이더+"다시 검출" → 닫기) + 툴바 오른쪽 끝에 여는 버튼 1개.
   - 검증: 3분할 레이아웃 렌더링(좌/중/우 리사이즈 정상)+툴바 통합 후 기존 R1~R4 골든패스
     (추론 실행, 원 자동검출/수동편집, 존 리스트, 블랍삭제) 전부 회귀 없음 — **레이아웃
     변경이라 이번 라운드는 리더가 "주요 기능 추가"에 준하는 실제 UI 조작 검증 요청**.
     팝업은 체크포인트 없이 단독 동작(이미지 로드 → 민감도 조정 → 재검출 → 개수/소요시간
     갱신 → 수동 원 편집 왕복) 확인.
2. **라운드 2 (요청 3, 저리스크지만 정확성 핵심 — root-cause 수정 포함)** —
   - 레이아웃: 라운드 1에서 신설한 툴바에 AI 신뢰도 `QSlider`+값 라벨, 픽셀크기
     `QSpinBox`를 추가(승인된 위젯 종류 — `QDoubleSpinBox` 아님, 위 판단 B 참고).
   - 기능: `_on_target_changed()`/`_current_target_mask()`의 마스크 소스를
     `raw_class_map`→`class_map`으로 교체 + 슬라이더/스핀박스를 `_on_target_changed()`에
     연결.
   - 검증: 신뢰도 차등을 가진 합성 `raw_class_map`/`confidence_map`으로 threshold
     0%/50%/100% 각각 적용 시 존 퍼센티지가 실제로 달라지는지 numpy 오라클과 대조(threshold
     변경이 화면 오버레이뿐 아니라 숫자에도 반영되는지가 핵심 확인 포인트), 블랍 삭제/원
     편집 등 R2~R4 회귀 없음.
3. **라운드 3 (요청 2, 최대 스코프 — 서브스텝 3개로 분할)**:
   - **3a. 좌측 패널 조립 — `InferenceImageList` 통합 + 애디티브 확장** — 승인된 좌측 패널
     (폴더 열기+경로표시 → 검색/정렬 → 상태아이콘+배지 목록 → 배치 컨트롤)을 라운드
     1에서 비워뒀던 좌측 슬롯에 채움. `InferenceImageList`에 `set_item_status()`/
     `clear_status()`(상태아이콘+배지), `set_multi_select()`/`selected_paths()`(다중선택)
     애디티브 API 추가(신규 검출/추론 로직 없음, 순수 UI 배선+위젯 확장). 검증: 폴더
     열기(재귀 스캔+트리+검색+정렬+경로표시) → 이미지 선택(자동 추론 실행 안 됨, 기존
     단일 이미지 흐름 그대로 유지 확인 — 위 "구현 시 확인 필요" 항목이 이 시점까지
     미확정이면 수동 트리거 유지로 확정) → 다중 파일 선택(`getOpenFileNames`) → Ctrl/Shift
     다중 선택(`selected_paths()` 반환값 확인) 전부 정상 동작, `inference_tab.py` 회귀
     없음(공유 위젯 애디티브 변경 검증 필수).
   - **3b. 일괄 처리 로직 + 결과 테이블 표시(엑셀 제외)** — 좌측 패널 하단 "1번째 이미지
     원을 전체에 적용" 체크박스(기본 체크)+"▶ 선택 이미지 일괄 처리 (N장)" 버튼 연결,
     진행률 다이얼로그 루프(처리 중 각 이미지의 상태아이콘을 대기→처리중→완료로 갱신 +
     완료 배지 표시), 해상도 방어 로직. 검증: 합성 폴더(이미지 3~5장, 크기 동일 1케이스 +
     크기 다른 1케이스, 알려진 타겟 마스크/원 배치)로 체크박스 두 상태(기본 재사용/개별
     자동검출) 각각 실행 → 테이블 값을 numpy 오라클과 대조, 진행률 취소 동작, 좌측 목록의
     상태아이콘/배지가 처리 진행에 맞춰 갱신되는지, 특정 이미지 재선택 시 일괄 처리
     결과와 100% 일치하는 값 재현 확인(캐시 없는 재계산 방식 검증).
   - **3c. Excel 내보내기** — `export_zone_percentages_to_excel()` 신설 + `zone_batch_result_dialog.py`의
     버튼 연결. 검증: 저장된 xlsx 셀 값이 화면 테이블과 일치.

각 라운드는 기존 관례대로 구현 → `python main.py` 실제 구동 검증 → 다음 라운드 순으로
진행한다.

  패널이 `clear()`로 리스트를 통째로 재구성해 선택/하이라이트 상태가 부당하게 리셋되던
  것"이 근본 원인이었다(수정 패턴: 캔버스를 상태의 단일 출처로 두고 getter로 재구성 후
  복원). 이번에 추가되는 `InferenceImageList` ↔ 캔버스 동기화, 배치 결과 브라우징에서도
  **"진짜 다른 이미지로 전환"과 "같은 이미지 안에서의 사소한 상태 변화"를 구분**해야
  한다 — 전자는 원/존 상태 초기화가 맞는 동작(기존 `_on_select_image()`가 이미 이렇게
  동작)이고, 이것은 버그가 아니다. 다만 배치 처리 진행 중(`QProgressDialog` 루프)에
  캔버스의 `set_circles()`/`set_pixmap()`을 반복 호출하면 매번 `circles_changed` 등이
  emit돼 사이드 패널이 불필요하게 재구성될 수 있으므로, **배치 루프 내부 계산은 캔버스
  API를 거치지 말고 `zone_metrics`/`circle_detector` 함수를 직접 호출**해야 한다(캔버스는
  기준 이미지의 원을 읽어오는 시점에만 `get_circles()`로 1회 조회).
- 20MP 이미지 폴더가 수십~수백 장이면 일괄 처리 소요 시간이 상당할 수 있음(1장당 추론+
  검출 수 초 예상, 실측은 구현/검증 단계) — `QProgressDialog` 취소 지원 필수, 현재 표시
  중인 이미지는 재추론 생략(캐시 재사용)하는 `inference_tab` 최적화를 그대로 적용.
- 판단 B의 `raw_class_map`→`class_map` 교체는 **표시용 마스크에만 영향**(존/블랍
  계산) — `refilter()` 자체나 원본 배열 저장 스키마는 건드리지 않으므로 회귀 범위가
  명확히 `zone_analysis_tab.py` 내부로 한정됨.
- 서로 다른 해상도가 섞인 폴더 + "기준 원 재사용" 모드의 비례 스케일 보정은 근사치다
  (완전한 카메라 캘리브레이션이 아님) — 배터리 캡 검사 워크플로우 전제(같은 카메라/렌즈/
  거리)상 실제로는 거의 발생하지 않을 예외 케이스에 대한 최소 안전장치일 뿐임을
  구현/검증 단계에 명시.
- 이 탭은 애초에 i18n 시스템을 쓰지 않는다(전 구간 하드코딩 한국어, `t()` 호출 0건 확인) —
  신규 UI도 동일 관례를 유지하면 되고, 별도 다국어 작업이 필요하지 않다.
- **`inference_image_list.py`는 추론 탭과 공유하는 파일** — 이번 라운드에서 애디티브
  API 2건(상태아이콘/배지, 다중선택)을 추가하지만, `_apply_display()`(필터·정렬 후 트리
  재구성)나 기존 `_build_*_tree()` 내부를 잘못 건드리면 추론 탭에도 회귀가 전이될 수
  있다 — 라운드 3a 검증은 반드시 **존 분석 탭뿐 아니라 추론 탭의 폴더 열기/검색/정렬/
  탐색(이전·다음) 골든패스도 함께 재확인**해야 한다.
- **다중 선택(`selected_paths()`)과 "현재 미리보기 중인 이미지"는 서로 다른 개념**이다 —
  `image_selected` 시그널(단일 아이템 클릭, 캔버스 미리보기 갱신용)과 Ctrl/Shift 다중
  선택(일괄 처리 대상 지정용)이 동시에 같은 트리 위젯에서 동작하므로, 이 둘을 혼동해
  "다중 선택하면 캔버스가 이상하게 뒤섞인다" 같은 새로운 BUG-018/019류 혼선을 만들지
  않도록 구현 시 명확히 분리할 것(다중 선택 중에도 캔버스는 마지막으로 단일 클릭한
  이미지만 계속 보여주면 충분 — Qt `QTreeWidget`의 `currentItem`과 `selectedItems()`가
  이미 개념적으로 분리돼 있어 자연스럽게 구현 가능).
